# 五泳池課表整合系統 — API 手冊

> 供第三方程式、IT 監控平台及內部自動化對接使用。
> Base URL：`https://<your-domain>`

---

## 認證

### 管理員端點

帶上 `x-admin-password` Header（與系統 `ADMIN_PASSWORD` 環境變數相同）：

```
x-admin-password: <ADMIN_PASSWORD>
```

或以 Query 參數：

```
?adminPassword=<ADMIN_PASSWORD>
```

**認證失敗回應：**

| 狀況 | HTTP | 說明 |
|------|------|------|
| 未帶密碼 | 401 | Unauthorized |
| 密碼錯誤 | 403 | Forbidden |

### 教練前台端點（`x-coach-token`）

教練透過 LINE OAuth 登入後取得 30 天 Session Token：

```
x-coach-token: <token>
```

Token 失效時伺服器回傳 `403 { "code": "session_expired" }`，前端自動導回登入頁。

### 公開端點

無需任何認證標頭，任何人皆可呼叫。

## 共用欄位說明

### 日期格式

所有日期欄位均為 `YYYY-MM-DD`（ISO 8601），時間戳為 UTC ISO 8601。

### 教練狀態（status）

| 值 | 說明 |
|----|------|
| `pending` | 申請中，尚未審核 |
| `approved` | 已核准 |
| `rejected` | 已退回 |

### POST `/api/admin/weekly-push/enqueue`

排入週推播工作至 pg-boss 佇列。

**認證：** 管理員

**Request body：**

```json
{
  "weekStart": "2026-05-18",
  "dryRun": false,
  "pushType": "weekly"
}
```

**冪等性：** 同一 `(pushType, weekStart)` 組合在 `queued | running | success` 狀態下不會重複排入。

**回應範例：**

```json
{
  "ok": true,
  "runId": "run_abc123",
  "status": "queued",
  "dryRun": false,
  "recipientCount": 152
}
```

## 錯誤格式

所有錯誤回應均為 JSON：

```json
{
  "message": "錯誤描述",
  "code": "OPTIONAL_ERROR_CODE"
}
```

常見錯誤：

| HTTP | 說明 |
|------|------|
| 400 | 參數格式錯誤或必填參數缺失 |
| 401 | 缺少認證標頭 |
| 403 | 密碼錯誤或 Token 失效（`code: "session_expired"`） |
| 404 | 資源不存在 |
| 409 | 資料衝突（如課表已鎖定） |
| 500 | 伺服器內部錯誤 |

## 接入服務說明

以下為已規劃或正在對接本系統的外部服務，以及各服務推薦使用的端點。

---

### 1. LINE 推播通知

**用途：** 每週課表確認後自動推播給教練，以及每日提醒。

| 情境 | 建議端點 | 說明 |
|------|----------|------|
| 週課表推播 | `POST /api/admin/send-weekly-notifications` | 手動觸發（cron 每週日 12:00 自動執行） |
| 明日提醒 | `POST /api/admin/notify-daily` | 手動觸發（cron 每日 19:00 自動執行） |
| 個別重推 | `POST /api/admin/send-notify-individual` | 指定教練重送 |
| 查看歷史 | `GET /api/admin/notify-logs?date=YYYY-MM-DD` | 確認特定日期推播狀態 |

**建議排程：** 週日 12:00（課表鎖定後）自動推週通知；每日 19:00 推隔日提醒。

---

### 2. IT 監控平台

**用途：** 外部監控儀表板（如 Grafana、自建 Dashboard）監測系統健康狀態。

| 情境 | 建議端點 | 說明 |
|------|----------|------|
| 系統健康 | `GET /api/deployment-test` | 無需認證，適合 uptime 監控 |
| IT 治理總覽 | `GET /api/admin/it-governance` | 服務狀態、功能旗標、API 目錄 |
| Ragic 同步狀態 | `GET /api/admin/ragic-status` | 確認資料同步是否正常 |
| 推播執行紀錄 | `GET /api/admin/weekly-push/runs` | 確認週推播是否成功 |
| 課程衝突警示 | `GET /api/conflicts/:date` | 監控排班衝突 |

**建議排程：** 每 5 分鐘 `/api/deployment-test`；每日早上確認 Ragic 同步狀態。

---

### 3. 課表排課版本對接（Swimming Class Scheduling Integration）

**用途：** 第三方系統（如家長通知 APP、場館顯示看板）拉取最新課表資料。

| 情境 | 建議端點 | 說明 |
|------|----------|------|
| 取得本週課表 | `GET /api/schedules?startDate=<Mon>&endDate=<Sun>` | 回傳指定週所有場館所有課程 |
| 特定場館課表 | `GET /api/schedules?startDate=...&endDate=...` 配合前端過濾 `venueName` | 目前 API 無場館篩選，由客戶端過濾 |
| 特定教練課表 | `GET /api/coach-schedules?coachName=...&startDate=...&endDate=...` | 查詢指定教練的排班 |
| 未指派課程 | `GET /api/schedules/vacant` | 找出尚缺教練的課程 |
| 衝突偵測 | `GET /api/conflicts/:date` | 確認特定日無排班衝突 |
| 課表鎖定狀態 | `GET /api/schedules/lock-status?venueName=...&startDate=...&endDate=...` | 確認課表是否已定版 |

**建議對接流程：**

1. 輪詢 `/api/schedules/lock-status` 確認課表已鎖定（`isLocked: true`）
2. 取得課表資料 `/api/schedules?startDate=...&endDate=...`
3. 依 `venueName`、`dayOfWeek`、`timeSlotId` 渲染課表
4. `isClassLocked: true` 代表課表已定版，可安全對外公告

---

### 4. Ragic 人事系統同步

**用途：** 將 Ragic 上的部門資料、教練姓名、LINE ID 及員工編號每日自動同步到本系統。

| 情境 | 建議端點 | 說明 |
|------|----------|------|
| 查看上次同步 | `GET /api/admin/ragic-status` | 確認同步時間與數量 |
| 手動強制同步 | `POST /api/admin/ragic-sync` | 不等每日 cron，立即同步 |

**同步規則：**
- 每日 03:00（台北時間）自動觸發
- 若 boot 時同步失敗，自動在 5 分鐘後、15 分鐘後重試
- 只同步 `active` 狀態教練；重複的 LINE ID 跳過（不覆蓋）

## 功能旗標（Feature Flags）

以環境變數控制各模組開關：

| 環境變數 | 預設 | 說明 |
|---------|------|------|
| `ENABLE_LINE_NOTIFY` | ON | LINE 推播模組 |
| `ENABLE_RAGIC_SYNC` | ON | Ragic 同步模組 |
| `ENABLE_SCHOOL_MODULE` | ON | 多校區模組 |
| `ENABLE_WEEKLY_PUSH_QUEUE` | **OFF** | pg-boss 週推播佇列（需手動開啟） |
| `ENABLE_WEEKLY_PUSH_WORKER` | **OFF** | pg-boss Worker（需手動開啟） |

設為 `0`、`false`、`off`、`no` 其一即關閉；`ENABLE_WEEKLY_PUSH_QUEUE/WORKER` 需設為 `1`、`true`、`on`、`yes` 才開啟。
